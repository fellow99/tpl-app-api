# 系统架构

> 项目：tpl-app-api（tpl-workspace 后端 — 用户侧 API）
> 生成日期：2026-08-22

---

## 一、架构概述

tpl-app-api 采用 **经典三层架构（Controller-Service-Mapper）**，基于 Spring Boot 4.1.0 构建，为前端（tpl-app-web）提供 RESTful API 服务。

## 三、核心设计决策

### 3.1 鉴权模型：轻量 Token 认证（非 RBAC）

- 使用 Sa-Token JWT 模式，登录后签发 Token
- `/auth/**` 路径通过 `@SaIgnore` 注解放行
- 其他所有路径通过 `SaInterceptor` 全局拦截，需登录
- **不实现细粒度 RBAC 权限模型**，仅区分"登录"和"未登录"

### 3.2 数据访问：MyBatis-Plus BaseMapper

- 所有 Mapper 继承 `BaseMapper<T>`，获得通用 CRUD 能力
- 自定义查询通过 `@Select` 注解写在 Mapper 接口上（无 XML 映射文件）
- 逻辑删除通过 MyBatis-Plus `delFlag` 字段自动处理

### 3.3 用户数据模型：用户表 + 档案表 + 视图

- `sys_user` — 用户核心信息（用户名、密码、状态）
- `tpl_user_profile` — 用户扩展信息（生日）
- `tpl_user_view` — 数据库视图，联表查询用户完整信息，供登录时一次查询获取

### 3.4 验证码机制

- 开发环境（dev profile）：`captcha.enable=false`，关闭验证码
- 生产环境（docker profile）：`captcha.enable=true`，启用验证码
- 验证码存储于 Redis，Key 格式：`captcha_codes:{uuid}`，TTL 5 分钟
- 验证码一次性消费（校验后立即从 Redis 删除）

  │                            │  register(req)       │                    │
  │                            │─────────────────────▶│                    │
  │                            │                      │ validateCaptcha()  │
  │                            │                      │──────Redis────────▶│
  │                            │                      │ checkUsername()    │
  │                            │                      │──────UserView─────▶│
